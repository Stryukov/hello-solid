# Reactivity Lab

Учебник по SolidJS и Ark UI в виде приложения: каждый урок — страница с теорией, живой
демкой и **счётчиками выполнений**. Числа в панели показывают, сколько раз выполнилась
каждая реактивная область. Именно они делают разницу между Solid и React осязаемой.

```bash
npm install
npm run dev
```

Дальше — http://localhost:5173

# Блок 0. Фронтенд с нуля — для тех, кто пришёл с бэкенда

Ровно тот минимум, чтобы дальше спотыкаться о Solid, а не о браузер, сборщик и синтаксис.
То же самое, но с примерами, есть в приложении — урок 00.

## Браузер и DOM

Браузер получает HTML и строит из него **дерево объектов** — DOM. Дальше HTML уже ни при
чём: страница это живой объектный граф в памяти, который браузер рисует на экран. Меняешь
объект в графе — картинка обновляется.

Аналогия: долгоживущий процесс, у которого в памяти висит дерево объектов, и любая мутация
этого дерева сразу отражается на выводе. Никакого «сформировали ответ и забыли» — процесс
живёт, пока открыта вкладка.

Работа фронтенд-фреймворка ровно одна: **держать DOM в соответствии с состоянием**.
Различаются фреймворки только тем, как решают, что именно поменять.

## Событийный цикл

Один поток и очередь задач — по сути тот же `asyncio`. Клик, таймер, ответ от сервера кладут
задачу в очередь, цикл разбирает её по одной. Тяжёлое синхронное вычисление блокирует
отрисовку так же, как блокирующий вызов внутри корутины вешает весь event loop.

### Почему здесь нет `.venv`

Это первое, что хочется сделать, приходя из Python, — и это не нужно.

`npm install` кладёт пакеты в `./node_modules` **внутри проекта**. В систему не попадает
ничего. Изоляция здесь по умолчанию: это pip аномален тем, что без venv лезет в систему,
npm так не делает никогда. В систему что-то попадает только при явном `npm install -g`,
которого в этом проекте нет.

`.venv` управляет `sys.path` для Python и на npm не влияет вообще — это разные экосистемы.

Настоящий аналог venv для Node — фиксация не пакетов, а **версии рантайма**: файл `.nvmrc`
и поле `engines` в `package.json`. Оба в проекте есть.

## Vite

Браузер не умеет ни TypeScript, ни JSX, ни импорт из `node_modules` по имени пакета. Vite —
dev-сервер и сборщик, который превращает всё это в понятный браузеру JavaScript.

В разработке он отдаёт модули по одному и умеет HMR: правишь файл — обновляется только он,
без перезагрузки страницы и без потери состояния. Для сборки собирает всё в `dist/`.

## TypeScript

JavaScript плюс типы. Ближайший знакомый аналог — `typing` в Python: синтаксис разный, идея
та же.

Главное отличие: типы **полностью стираются при сборке**. В рантайме их нет вообще —
никакого аналога `pydantic`, проверяющего данные на входе. Тип это договор с компилятором
и редактором, а не защита от кривого ответа сервера. Данные с бэкенда всё равно придётся
валидировать руками.

## JSX

Выглядит как HTML внутри кода, но это не шаблонизатор, а синтаксис, который **компилируется
в обычный JavaScript**. И вот здесь начинается Solid.

В React `<div>{count}</div>` превращается в вызов, создающий описание элемента; React потом
сравнивает описания между собой и решает, что поменять в DOM. Это виртуальный DOM.

В Solid тот же JSX компилируется в код, который **создаёт настоящий DOM-узел один раз** и
подписывает конкретный текстовый узел на конкретный сигнал. Виртуального DOM нет, сравнения
деревьев нет.

Из этого следует всё остальное:

- тело компонента выполняется **один раз** за свою жизнь;
- значит, не нужны ни `useMemo`, ни `useCallback`, ни правила хуков, ни массивы зависимостей;
- значит, обычные переменные в теле компонента живут вечно и не пересоздаются.

Урок 02 показывает это на счётчиках.

## Tailwind

Вместо отдельного файла со стилями — служебные классы прямо в разметке: один класс ≈ одно
CSS-свойство. `px-4` это `padding-inline: 1rem`, `flex` это `display: flex`.

Для новичка это скорее плюс: учишь сами CSS-свойства, не воюя с каскадом и специфичностью.
В Tailwind 4 конфига-файла больше нет — токены объявляются прямо в CSS через `@theme`,
смотри `src/index.css`.

## Чего не делать

Почти вся литература по фронтенду написана про React, и часть её в Solid **активно вредна**.
Если в найденной статье встречаются слова «ререндер», «правила хуков», «`useMemo` для
оптимизации», «массив зависимостей» — к Solid это не относится.

Ты в удачной позиции: разучиваться не придётся.
